# ags5_concept — HTTP-streaming `.ags5db` demo

**Live demo:** <https://niko86.github.io/ags5_concept-demo/>

A multi-megabyte AGS5 geotechnical database, opened entirely in your
browser. DuckDB-wasm uses HTTP Range requests over `httpfs` so only
the bytes a given query touches travel over the network. **No backend,
no Python, no GINT/HoleBASE license.** Open DevTools → Network and
watch the partial fetches.

This is the **public companion repo** for
[niko86/ags5_concept](https://github.com/niko86/ags5_concept). It exists
to host the demo's static assets and synthetic dataset; everything that
makes the demo *work* (the registry-driven AGS5 codec, the typed-column
DuckDB schema, the marimo notebook source) lives in the main repo.

## What's here

| File | Purpose |
|---|---|
| `index.html` + `assets/`, `files/` | marimo wasm runtime (Pyodide + DuckDB-wasm + the `db_browser_remote.py` notebook). Regenerated by `marimo export html-wasm ...` in the main repo. |
| `large_synthetic.ags5db` (~96 MB) | Synthetic Phase 7A dataset: 50 boreholes × 1 sample × 1 triaxial test × 22,500 TREL time-step readings = 1.125M rows. Built by `examples/build_synthetic_demo.py`. |
| `.nojekyll` | Suppresses GitHub Pages' Jekyll processing so the leading-underscore folders in marimo's bundle ship intact. |

## How the demo works

1. Page loads. Pyodide bootstraps DuckDB-wasm in the browser.
2. The notebook ATTACHes `large_synthetic.ags5db` over `https://`.
3. Every SQL query in the notebook is compiled by DuckDB-wasm and
   serviced via HTTP Range requests against the file's storage
   segments. A `COUNT(*)` reads a few KB of metadata; a `SELECT * FROM
   v_loca LIMIT 50` reads just the LOCA storage blocks.
4. The notebook drives off the `_spec_*` self-describing tables
   inside the database — never imports `ags5_models`. Any Phase-6.5
   compatible `.ags5db` opens the same way.

## Trying it locally

```bash
git clone https://github.com/niko86/ags5_concept-demo
cd ags5_concept-demo
python -m http.server 8000
# open http://localhost:8000
```

## Pointing at your own file

The notebook reads its URL from the `?url=` query string:

    https://niko86.github.io/ags5_concept-demo/?url=https%3A%2F%2Fexample.com%2Fmy.ags5db

The host has to provide **CORS** and **HTTP Range** support, which
`raw.githubusercontent.com` does natively. S3 with appropriate
configuration works too. Private GitHub URLs do **not** work — DuckDB-wasm
can't supply custom auth headers.
